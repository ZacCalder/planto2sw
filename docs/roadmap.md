# Roadmap

## 現況（2026-09-13）

**用途**：工具而家主要用嚟**睇費率**同**對賬**；匯入記賬呢條路已暫停（決定 18）。

- **睇費率**：上傳一份 Planto CSV 之後，第 3 步嘅費率表按「卡 × 場景」列出引擎算到嘅有效費率、筆數同金額，
  可以逐格手改覆蓋。冇獨立查率界面：唔上傳 CSV，費率表唔會顯示。
- **對賬**：`rewardcash_recon.py`（V1）存 RewardCash 餘額快照，按結單日列每期應得 RC（Pulse 另計 RMB 側），
  再比對兩個快照嘅差額。要喺 config 填 `rewardcash_map`。
- **匯入**：瀏覽器版（前置 + 五步：貼現有備份 → 優惠設定 → 上傳 CSV → 逐筆檢查 → 生成轉移碼）同 CLI 都仲用得，
  測試照跑，亦曾經喺真實瀏覽器走完全程再匯入網頁版碌邊張核對過（追蹤頁月度合計 = 記賬 rebate 之和）。
  但唔再推進，亦唔建議用嚟同步真實交易：匯入係整份覆蓋，而且會將 `rate`／`rebate` 永久寫死。

**點解工具要自己計回贈**：碌邊張匯入時會將每條記賬照寫入嘅樣儲存，之後永遠唔會重新判類別、亦唔會重算回贈——
每條記賬顯示嘅回贈都係儲存咗嘅 `rebate`（讀法係 `rebate || 0`）；追蹤頁嘅總數會再用呢個儲存值反推有效率、按上限調低超出嘅部分，但冇任何地方會重算一條記賬嘅類別或者回贈，唯一會重算嘅情況係用戶逐筆打開一條記賬再按儲存。所以工具一定要喺匯入之前
自己分類、自己計好回贈，呢個就係工具有自己費率引擎嘅原因（決定 7、22）。

**費率引擎凍結喺碌邊張 app 2.0.4（2026-09-11）**，之後唔再更新（決定 22）：

- 基本費率同商戶優惠照讀用戶自己嘅 `app-data.json`。
- 計法（逐張卡嘅分支、Travel Guru 年度 RC 上限、EveryMile 季度門檻）硬編碼喺引擎入面，停喺 2.0.4。
  碌邊張之後改計法嘅話，工具同 app 會有出入，一切以 app 為準。凍結日期喺第 3 步費率表上方、CLI 每次運行、
  README 三語都有寫。
- `tests/engine_check.py` 只對本機已快取嘅 2.0.4 bundle 做離線核對（209,664 組零差異）；倉庫唔附帶 bundle，
  亦唔提供下載（決定 23）。

**`app-data.json` 由用戶自備**（決定 20）：瀏覽器版喺「前置」步驟收檔，「一鍵攞最新」淨係用戶明確撳掣先會
fetch，載入、定時、重試都唔會；`planto2sw.py` 完全唔連網。兩邊都顯示 `generatedAt` 日期，超過 30 日出更新提示。

本工具係非官方工具，同碌邊張冇關係；聲明喺 README 三語、`index.html` 頁首頁尾同兩個 CLI 嘅 `--help`（決定 21）。

## 已知限制

1. **逐張卡嘅簽賬上限冇建模**：`capAmt`／`sharedCap`／爆頂後嘅降率（例如 Pulse 內地嘅半年上限）工具完全唔處理，
   簽過上限嗰部分嘅回贈會算多。引擎已凍結，唔會再補。已建模嘅上限淨係 Travel Guru 年度 RC 上限同 EveryMile 季度門檻。
2. **EveryMile 季度**取記賬所在季度，唔係「今日」所在季度（決定 13）。
3. **Pulse 內地網上消費（`SALES:` 前綴）算唔算 Travel Guru** 未確認；而家照計（決定 9），可以用對賬核對。

## 仲要做

1. **RewardCash 對賬**：確認 HSBC 喺結單日後幾日先入賬，據此調整比對視窗。
2. 用對賬結果核對上面第 3 項（Pulse 網上消費嘅 Guru）。

## 唔再做
